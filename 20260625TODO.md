## Competitor-Parity Feature Backlog (easiest → hardest to add)

Popular in Xero/QuickBooks/Sage/Wave/FreshBooks, currently missing here.

1. Quotes / estimates (+ accept & convert-to-invoice). Reuse the whole
   `sales_invoices` machinery; add `document_type` `quote`/`estimate`, an accept
   action, and a quote→invoice copy. Lowest effort — mostly reuse.
2. General fixed-asset register + depreciation schedules (straight-line /
   reducing-balance) for owned assets. Depreciation math + monthly journals
   already exist for leases (`finance_lease_amortization.py`, `finance_lease_gl.py`);
   generalise to an owned-asset table.
3. Online invoice payment ("Pay now" via Stripe/PayPal). Receipt posting already
   exists (`post_customer_receipt_atomic`, `customer_receipts.py`) and inbound
   webhook infra exists (`webhooks.py`); add gateway + payment link + webhook→receipt.
4. Purchase orders / procurement (PO → approval → match to supplier bill). New
   module mirroring the sales-invoice structure; adds PO↔bill matching.
5. Live bank feeds / Open Banking (Plaid / TrueLayer / Yodlee). Statement-line
   normalisation + dedup already exist; add per-bank OAuth + scheduled feed sync.
6. True multi-currency (FX rate table, per-txn rate, revaluation, exchange
   gain/loss). Currency is only a label today; this touches schema + GL posting broadly.
7. Tax-authority e-filing (e.g. HMRC MTD / SARS eFiling) beyond the current VAT
   summary. Jurisdiction-specific external APIs + compliance.
8. Payroll (employees, PAYE/statutory, pay runs, payslips). Whole new domain — highest effort.

Frequent user complaints about accounting software; note where APFlow already covers it.

1. Invoice delivery tracking + one-click resend (opens/deliveries). `sales_invoice_delivery_events`
   already logs queued/sent; surface status in the UI and add a resend action.
2. Attach supporting documents to any transaction (journals, invoices). `bank_attachments`
   already does this for bank lines; extend the pattern to journals/sales invoices.
3. Guided onboarding to reduce the "steep learning curve" complaint. `go_live_checklist`

4. Easy correct/undo of posted entries. Bank unpost/reversal already exists
   (`bank_rules_journal_preview_unpost`); extend reversal UX to GL/sales-invoice posts.
5. Customer self-service portal (tokenised public link to view/download/pay an
   invoice + see statement). Reuses PDF + statement services; add public tokenised routes.
6. Better invoice branding/customisation (logo, colours, layout). `branding_snapshot`
   exists but PDF is hand-drawn PyMuPDF; move to an HTML/template renderer for flexibility.
7. Custom/saved report layouts (rigid-reports complaint). Reports are comprehensive
